# Nestory 产品愿景

状态：愿景草案 v0.1

更新日期：2026-07-21

产品工作名：`Nestory`

原型名：`RoomRecall`

> A memory system for your home.
>
> 让家拥有一份可以查询、可以信任、也可以被行动调用的记忆。

这是一份产品愿景，不是当前版本的 Build Spec。它描述我们希望长期创造的用户价值、必须坚持的边界，以及验证产品是否值得继续投入的证据。当前 V1 范围仍以 `docs/nestory-v1-prd.md` 和 ADR-0001 为准；新的 V1.x Spec 只有在 Wayfinder 决策和真实用户验证完成后才会产生。

## 1. 我们看见的问题

数字世界里的信息可以搜索、分类、回溯和恢复，但物理世界里的东西没有天然的记忆层。

一件物品被放进抽屉、柜子、收纳箱或行李袋以后，会逐渐从人的注意力中消失。时间足够久之后，用户可能经历三个层次的遗忘：

1. 记得拥有，但忘了放在哪里。
2. 记得有类似的东西，但不确定数量、状态和是否还能使用。
3. 完全忘记自己买过，于是在需要时重新购买。

这种遗忘不只浪费寻找时间。它还会带来焦虑、重复购买、替代品闲置、空间拥挤，以及“东西很多但真正需要时仍然没有”的失控感。

现有解决方式通常是纸箱标签、手机相册、备忘录、购物记录、电子表格，或者依靠记忆。这些工具记录的是碎片，不理解物品与房间、柜子、容器、任务和时间之间的关系，也很难在生活发生变化后保持可信。

## 2. 我们相信什么

人们不需要维护一个完美的家庭数字孪生，也不愿意像管理仓库一样管理自己的家。

他们需要的是：在物理生活变复杂的时刻，系统能够以很低的维护成本恢复关键记忆，并帮助他们做出下一步决定。

因此，Nestory 的价值不在于记录了多少件物品，而在于它是否在正确的时刻帮助用户完成了一个真实结果：

- 找到一件被收起来的东西；
- 确认家里已经拥有某类物品；
- 在购买前发现可用的同类物或替代品；
- 为搬家、旅行、健身或维修准备完整装备；
- 重新安置、使用、出售、捐赠或舍弃不再值得占据空间的东西。

## 3. 产品愿景

Nestory 希望成为家庭物理世界的个人记忆层。

它帮助用户知道：

- 家里有什么；
- 东西现在在哪里；
- 正常情况下应该放回哪里；
- 这个判断来自什么证据，是否仍然可信；
- 已有物品能否满足一个新的任务；
- 哪些东西值得继续保留、重新使用或退出生活空间。

长期来看，用户应该可以像查询数字文件一样自然地查询自己的物理生活，同时不需要先完成一次沉重、完整、精确的盘点。

## 4. 最初为谁服务

第一目标用户是：未来三个月内正在搬家或刚搬完家、居住在城市小户型、拥有较多箱子、袋子和活动装备的租房者。

这类用户具备三个重要条件：

- 痛点集中：物品在短时间内大量移动并失去可见性；
- 录入动机足够强：打包本身就是一次自然的 Capture；
- 可以验证长期价值：搬家建立的 Home Memory 可以继续服务寻找、装备准备、购买判断和断舍离。

搬家不是产品的最终边界。它更像是建立第一份 Home Memory 的高动机入口。

## 5. 五个核心动作

### 5.1 Remember：记得

系统帮助用户记住自己拥有什么，包括长期藏在深处、已经退出注意力的物品。

重点不是完整盘点，而是对高价值、难替代、容易遗忘、与 Operation 有关的 Belonging 建立足够可信的记忆。

### 5.2 Retrieve：找到

用户知道自己拥有某件东西时，可以快速得到它所在的 Room、Furniture、Container、箱子或非房间状态，并看到时间、置信度和证据。

当系统不确定时，它应该给出候选位置和下一步行动，而不是编造一个肯定答案。

### 5.3 Reuse：复用

当用户想购买一件东西时，系统先回答：

- 家里是否已经有同类物品；
- 是否有可以完成同一任务的替代品；
- 它们在哪里、数量如何、是否还能使用；
- 是否真的需要购买新的。

Nestory 不以阻止消费为目标，而是减少因为家庭记忆缺失而发生的无意识重复购买。

### 5.4 Ready：准备

当用户表达一个意图，例如搬家、健身、旅行、露营、维修或季节整理，系统把意图展开为所需物品，合并重复要求，检查可用替代品，并生成按取物位置组织的 Retrieval Plan。

家的物品因此不只是库存，而是可以被任务调用的能力。这一层可以称为 **Home Capability**。

### 5.5 Release：放下

系统通过 Declutter Review 帮助用户看见重复、长期隐藏、过期、损坏、低使用或高空间成本的物品。

它提供保留、重新收纳、轮换使用、出售、捐赠、回收、舍弃和暂缓判断等选项。目标不是丢得更多，而是让用户有意识地决定什么值得继续占据生活空间。

Nestory 不替用户判断情感价值，也不使用羞耻、打卡压力或强制目标推动断舍离。

## 6. 产品闭环

Nestory 希望建立以下长期循环：

```text
Capture
  -> Remember
  -> Retrieve
  -> Reuse or Ready
  -> Release or Re-home
  -> Better Home Memory
```

搬家、季节变化、一次寻找失败、一次重复购买、一个变得混乱的 Container，都可以成为更新这份记忆的自然触发点。

系统的维护不应依赖用户定期打开 App 做“库存劳动”。每一次真实 Operation 都应该顺便让 Home Memory 变得更准确。

## 7. 最重要的用户旅程

### 7.1 搬家与拆箱

用户拍摄一个箱子、说一句话或快速补充文字，系统形成内容提案并让用户确认。到达新家后，用户可以在 30 秒内找到一件重要物品所在的箱子，并知道今晚或本周应该先拆什么。

### 7.2 找回被遗忘的物品

用户问“我是不是买过转换插头”或“家里有没有备用胶带”。系统既搜索准确名称，也理解类别、同义词和可能的替代品，并说明答案可信到什么程度。

### 7.3 购买前回忆

用户准备购买时查询某一类物品。系统展示已有数量、位置、状态和替代关系，让用户在完整信息下决定购买、复用还是暂缓。

### 7.4 Intent Kit 与 Home Capability

用户说“我要去健身”或“我要修椅子”。Agent 根据 Kit Requirement 组合已有物品、发现缺失项，并生成按位置组织的取物计划，而不是只返回一个通用清单。

### 7.5 Declutter Review

系统在搬家、季节整理或空间过载时，解释为什么某些物品值得重新判断。用户做出的保留、重新安置或释放决定会回写 Place Graph，使下一次查询更准确。

## 8. 产品应该如何工作

### 8.1 Place Graph 是事实基础

Room、Zone、Furniture、Container、Belonging、Placement、Evidence、Operation 和 Intent Kit 通过 Place Graph 连接。

列表、搜索、Agent、2D、3D 和扫描都只是读取或更新同一份 Home Memory 的不同界面，不能各自维护互相矛盾的事实。

### 8.2 Capture 必须渐进而非沉重

用户可以通过文字、语音、照片、Container Snapshot、商品信息和后续可能的 Room Scan 创建 Observation。

产品应该优先选择达到当前任务所需的最低精度：如果一个箱子照片已经能够解决寻找问题，就不要求用户扫描整间房；如果只需要类别和 Container，就不强迫用户记录精确坐标。

### 8.3 不确定性必须可见

所有自动识别、Agent 推理和视觉结果都只是 Proposal。系统必须保留 Evidence、时间和置信度，并经过用户 Review 和 Commit 才能进入可信的 Place Graph。

未知位置必须保持未知。系统不能为了让界面流程看起来完整，就把候选物品塞进一个没有证据的抽屉或柜子。

### 8.4 更新成本必须低于记忆价值

产品只在真实生活发生变化时请求最小必要确认。一次纠错、拆箱、购买判断或断舍离决定，都应该顺便更新系统，而不是产生另一份待维护的任务。

## 9. Agent 的角色

Agent 是 Home Memory 的查询者、解释者和 Operation 协调者，不是事实来源。

它可以：

- 理解模糊物品名称、类别和替代关系；
- 把广泛意图拆成 Kit Requirement；
- 合并重复需求并生成 Retrieval Plan；
- 解释位置答案、证据和不确定性；
- 建议下一次 Capture、Correction 或 Declutter Review；
- 在购买前指出已有物品和可用替代品。

它不能：

- 在没有工具返回或 Evidence 的情况下声称看见某件物品；
- 绕过用户确认修改 Place Graph；
- 根据弱证据判断物品“没用”或应该丢弃；
- 默认把家庭照片、证件、屏幕或地址暴露给外部模型。

## 10. 扫描、2D 与 3D 的位置

视觉扫描、2D 和 3D 是 Capture、Correction、Planning 和 Trust 层，不是产品愿景本身。

- Container Snapshot 可能比全屋重建更早产生真实价值；
- 2D 适合精确调整位置、尺寸和关系；
- 3D 适合快速理解空间、检查比例和发现明显错误；
- Room Scan 只有在真实用户证据证明其明显降低录入成本或提升可信度时，才进入 V1.x Build Spec。

Nestory 不承诺一次手机扫描就自动获得完美的 1:1 家庭真相。

## 11. 隐私与信任

家是高度私密的空间。照片和视频可能包含人脸、地址、证件、药品、账单、屏幕和生活习惯。

默认原则是：

- 本地优先；
- 最少采集；
- 明确说明哪些数据会离开设备；
- 敏感区域可以在上传或进入 Agent 上下文前被遮挡；
- 原始媒体可以删除，同时保留最小、可解释的结构化 Evidence；
- 用户能够查看、纠正、导出和删除自己的 Home Memory。

信任优先于自动化率。一次诚实的“不确定”比一次自信的错误位置更有价值。

## 12. 产品体验原则

### 安静而实用

界面应该像一个可靠的家庭助手，而不是仓库 ERP、游戏化打卡工具或炫技型 3D 展示。

### 行动优先

首屏优先显示用户下一步需要处理的事情：待确认的 Proposal、正在进行的 Move、缺失的 Kit Requirement、过期的 Container Snapshot，而不是装饰性视觉效果。

### 渐进精度

先记录“在书桌抽屉”，只有任务真的需要时才补充“右侧第二格、靠后”。

### 容许生活混乱

物品会被临时放置、带出门、借出、清洗、消耗和遗失。系统必须支持这些状态，而不是假设所有东西永远待在固定坐标。

### 不制造内疚

对于重复购买、混乱和断舍离，产品提供证据与选择，不评价用户的人格或生活方式。

## 13. 我们不做什么

Nestory 不是：

- 要求录入每一件廉价物品的家庭仓库系统；
- 以完美 3D 数字孪生为前提的房间建模工具；
- 持续监控家庭和人物行为的摄像系统；
- 通用室内设计 CAD；
- 自动决定购买、丢弃或整理方式的权威；
- 用焦虑推动消费或用羞耻推动极简的产品；
- 没有 Evidence 却给出确定答案的聊天机器人。

## 14. 成功意味着什么

愿景层的北极星不是“录入物品数”，而是 **Trusted Home Outcomes**：用户依靠一条可信 Home Memory，成功完成了一次寻找、复用、准备或释放决定。

需要验证的核心指标包括：

- 首次用户能否在五分钟内建立第一条可信记忆并得到一个有用答案；
- 搬家用户能否在 30 秒内找到重要物品所在的箱子；
- 用户是否会在购买前主动查询，并因此复用已有物品或避免重复购买；
- 用户是否能通过 Declutter Review 释放空间，而不感到被系统评判；
- 每次更新 Home Memory 所花的时间，是否显著低于它节省的寻找、购买和整理成本；
- 错误答案是否能被快速纠正，并保留可解释的历史；
- 搬家结束后，是否仍有足够多的 Ownership Recall、Intent Kit 和 Declutter Review 使用场景让用户回来。

## 15. 分阶段实现愿景

### 阶段一：在高动机事件中建立可信记忆

- 搬家、装箱和拆箱；
- Container Snapshot；
- 重要物品寻找与纠错；
- 第一晚、第一周和 Intent Kit 的 Retrieval Plan。

### 阶段二：让 Home Memory 产生长期回报

- Ownership Recall；
- 类别搜索和替代品；
- 购买前查询；
- 低成本状态更新；
- Declutter Review 和季节整理。

### 阶段三：只引入被证据证明必要的空间智能

- 有界的 Room Scan；
- 共享坐标下的 2D Correction；
- 3D Trust Review；
- 家具尺寸、碰撞和小空间规划。

每个阶段都必须证明上一阶段产生的 Home Memory 值得继续维护。技术能力不能替代产品证据。

## 16. 愿景叙事

一个用户准备搬家。她没有逐件建立库存，只是在封箱前拍了一张照片，说“第一晚用品，去卧室”，系统生成内容和目的地提案，她快速确认。

到达新家后，她问“转换插头在哪”，系统回答“卧室 03 号箱，照片中靠近充电器，置信度中等”，并提示这个箱子还包含第一晚需要的床头灯和药品。

几个月后，她准备再次购买转换插头。Nestory 提醒她家里已经有两个，一个在书桌抽屉，一个仍在旅行包里。她不再购买，而是把旅行包里的那个放回 Default Home。

季节整理时，系统发现同一个抽屉里有三个功能重复的旧充电器，并解释它们长期未出现在任何 Operation 中。她保留一个、捐出一个、回收一个。完成后，Home Memory 和现实空间同时变得更清晰。

这就是 Nestory 希望创造的体验：不是更努力地管理物品，而是让家替人记住，让已有的东西重新可见、可用，也让不再需要的东西更容易被放下。

## 17. 最简表达

### 一句话

Nestory 是一套家庭记忆系统，帮助你记得拥有什么、找到它们、优先复用已有物品，并有意识地放下不再需要的东西。

### 对用户的承诺

> 让家替你记住。

### 产品判断原则

> 如果一项功能不能以更低成本帮助用户记得、找到、复用、准备或放下，它就不应该进入产品。

## 18. 仍待验证的问题

- 用户是否愿意在搬家或装箱时完成足够轻量的 Capture？
- 搬家建立的 Home Memory 是否会在三个月后继续产生价值？
- “购买前先问家里”是否能形成稳定行为，而不只是偶尔想起？
- 哪些类别最容易产生 Ownership Recall 和替代品价值？
- Declutter Review 是否能帮助用户行动，而不是增加另一份待办压力？
- 谁是长期受益者，谁愿意为哪一种结果付费？
- Container Snapshot 是否已经足够，Room Scan 和 3D 是否真的降低了总维护成本？

这些问题必须通过目标用户和真实生活流程验证，不能由原型完成度或模型能力替我们回答。
